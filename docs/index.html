What one click actually provisions

No magic, no proprietary formats. Everything Hostzilla writes is ordinary config you could have written yourself.

Apache virtual host

Its own vhost with directory indexes off and dotfiles denied, so a stray .env or .git is never served.

Isolated PHP-FPM pool

A dedicated pool and Unix socket per site, with open_basedir confining PHP to that site's document root.

MySQL database and user

A database, a dedicated user, and a randomly generated password — scoped so one site cannot read another's data.

Free SSL, when DNS is ready

Opt in and Hostzilla runs certbot — but only after checking the domain actually resolves to this server, so you never burn rate limits.

WordPress, configured properly

Core downloaded, wp-config.php written with your credentials and freshly generated auth salts — not the sample placeholders.

A job queue you can watch

Every provisioning run is a job with live status and full logs, so a failure tells you which step broke and why.

Built to keep root at arm's length

A control panel needs root to do its job. The design question is how narrow the path to it is.

The panel never runs shell

It builds an argument array, never a command string, and never invokes a shell interpreter.

Three verbs, listed literally

Sudo permits exactly site_create, site_delete and site_list. No wildcard paths, no shell in the allowlist.

Validated twice, trusted once

The panel validates for your benefit; the root-owned verb validates again for everyone's. Neither trusts the other.

Failures roll back

A create that dies halfway undoes its own work, so you are never left with a half-provisioned site you cannot retry.

The full threat model — including the weaknesses, which are stated plainly rather than left for you to discover — is in SECURITY.md.

Where Hostzilla actually is

It is v0.1. Here is the honest split, so you can decide whether it is useful to you today rather than finding out after you install it.

Works today

  • One-command install on fresh Ubuntu 22.04 / 24.04
  • Static, PHP and WordPress sites
  • Per-site vhost, PHP-FPM pool, database and user
  • Let's Encrypt SSL when DNS points here
  • Delete a site, including its database
  • Job queue with live status and logs

Not built yet

  • Visual / drag-and-drop site builder
  • Email hosting, DNS management, backups
  • Multiple panel users, resellers, billing
  • nginx support — Apache only
  • Editing a site after it is created

Know before you deploy

  • All sites run as www-data — not hostile-tenant isolation
  • One operator account, no roles
  • Assumes it owns Apache, PHP-FPM and MySQL on the box
  • Plain HTTP until you put a certificate on the panel
